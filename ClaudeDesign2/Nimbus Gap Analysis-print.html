find_in_page Nimbus · Gap Analysis

What Nimbus
doesn’t (yet) cover.

The designer mockup contains 14 patterns that the official Nimbus docs either don’t address at all, cover only partially, or contradict outright. These gaps aren’t „Nimbus is bad“ — they’re „Nimbus needs an application-layer extension“. For the NextGen AdminConsole we’ve already built every one of them into _shared/expireon-app.css — the designer effectively predicted what Nimbus needs next.

Critical Gaps

every admin page needs them — not in Nimbus
G1

KPI / Stat Card pattern

Four big numbers up top — the first visual anchor on any datatable page. Mockup shows a centered mega-number with the label above and a delta indicator below.

NimbusOnly generic .card + .card-body. No KPI-specific tokens for number size, centering, delta indicator.
We built.kpi-strip, .kpi, .kpi-value (3.25rem), .kpi-delta.up/down/neutral
Critical
G2

App shell composition

How sidenav + topnav + main scroll area + canvas margins fit together — with the right heights and z-index layers.

NimbusComponents documented individually. No layout template showing how they combine — header height, sidenav width variable, body scrolling.
We built.app-main, .app-scroll, .app-canvas with max-width 1440. Sidenav override CSS in _shared/sidenav.js.
Critical
G3

Avatar component

Every user list, every audit entry, every comment UI needs avatars. Mockup shows purple-gradient bubbles with initials.

NimbusNot documented. There’s .flags (country icons) — but no user-avatar component with initials, sizes, or a status indicator dot.
We built.avatar-bubble with a gradient BG sourced from the Expireon token. Plus .icon-tile as a variant for entity icons.
Critical
G4

Datatable toolbar (compound)

Search field + Search button + filter funnel + Show dropdown + view-toggle + Export dropdown + primary CTA in one row. A complex compound pattern.

Nimbustoolbars.css exists (basic layout), but no documented datatable toolbar with that specific control composition.
We built.toolbar-v2 with all sub-patterns: .toolbar-search, .icon-funnel-btn, .show-control, .view-toggle.
Critical
G5

Pagination · rows-per-page

„Rows per page: 10 ▼ · 1–10 of 100 · « ‹ › »“ — the standard pagination of any modern datatable.

NimbusOnly Bootstrap-compatible numbered .pagination (1/2/3) and a short .pagination-toolbar. No rows-per-page + range + arrows-only.
We built.pager + .pager-rpp + .pager-range + .pager-arrows. A new component altogether.
Critical
G6

View toggle: Table ↔ Cards

Two connected icon buttons, one active. Standard for lists that can also render as a card grid — relevant for the entire P2 family.

NimbusNot documented. buttongroup.html exists in the docs, but no toggle-group pattern with an active state.
We built.view-toggle with aria-label + JS active-state sync. Extensible to further view modes.
Critical

Major Gaps

partially documented or application unclear
G7

Section strip / caps locator

„ON-PREM | ENDPOINTS“ as a slim caps strip at the top of the canvas. Replaces the classic breadcrumb.

NimbusHas breadcrumb.css (Bootstrap style with chevrons). No caps-strip pattern for the page locator.
We built.section-strip with 0.18em letter-spacing + divider.
Major
G8

Page eyebrow (instead of H1)

All-caps headline 0.875rem as the only page headline. Typographically unusual but explicitly chosen in the mockup.

NimbusHas heading modifiers (.bold, .light) for h1–h6. No „eyebrow as page title“ pattern. Doesn’t appear in the docs either.
We built.page-eyebrow h1 with 0.12em letter-spacing + uppercase.
Major
G9

Filter row (always-on) + active chips

Filter selects permanently visible below the toolbar + active filters as removable chips.

Nimbuschips.css exists (basic chip), but no „active filter as chip“ UX pattern and no filter-row pattern.
We built.filter-row + .filter-chip with close button.
Major
G10

Split button / „Export as ▼“ dropdown

Secondary button with a caret indicator for format selection. A classic SaaS pattern.

Nimbusbuttongroup.html + dropdown.css exist, but no documented split-/dropdown-button pattern.
We built.btn-dropdown with arrow_drop_down material icon.
Major
G11

Datatable v2 — header & cell tokens

Column headers in tiny caps with 0.08em letter-spacing, inline sort indicator, compact 11px headers. First column with icon tile + two-line stack.

Nimbustables.css documents the base table + .table-hover. No spec for caps-header typography, sort indicator, stack cells, mono cells.
We built.th-sort, .cell-stack, .cell-primary, .cell-secondary, .cell-mono, .cell-avatar.
Major
04

Conflicts — Nimbus says A, designer does B

needs to be resolved
C1

Sub-nav active state: stripe vs. pill

Nimbus shows in cnds-sidenav.html a 3 px accent stripe on the left (box-shadow: inset 3px 0 0 var(--cnds-product-accent)) + soft background. The designer mockup uses a full rounded pill background instead, no stripe.

Nimbus official3 px stripe on the left + soft BG. Currently implemented in our _shared/sidenav.js.
Designer mockupFull pill with rounded background, no stripe.
Conflict
C2

Status: badge pill vs. colored text

Nimbus badges.css defines .badge-dot.badge-success as a pill with BG + dot. Designer mockup shows status as colored text with a small dot, without pill background.

Nimbus officialPill + dot + text with BG tint.
Designer mockupOnly colored text + dot, no pill BG. → We built a .status class as the hybrid.
Conflict
C3

Header logo size: 40 px (spec) vs. 32 px (mockup)

Nimbus sidenav.css specifies .sidenav-header img { max-height: 40px }. The designer mockup shows the Expireon logo noticeably more compact — around 26–30 px.

Nimbus officialmax-height: 40px
Designer mockup~28 px tall — we use 32 px in the current sidenav. Slightly off.
Conflict
05

What this means for Nimbus

Nimbus is a solid foundation DS — but not an app DS.

What Nimbus delivers: tokens, primitives, base components (buttons, cards, tables, badges, forms, alerts, modals). That part is genuinely clean and consistent. What Nimbus doesn’t deliver: application patterns — the compositions on top of the primitives that turn into an actual SaaS admin UI.

The designer essentially predicted what Nimbus needs as an application layer. Every single gap on this list should land in Nimbus v2 (or a Nimbus-Apps add-on), because the other Cloudficient apps (CaseFusion, Hyperlize) need exactly the same patterns.

Our _shared/expireon-app.css is effectively a first draft of the Nimbus application layer — 14 patterns I’d hand back to the Nimbus maintainers.

06

Proposal

  1. Pass this list to Scott Williams (Nimbus author). Plus our finished CSS snippets from expireon-app.css as a reference implementation.
  2. Extend the Nimbus roadmap with an „Application Patterns“ layer: KPI cards, app shell, datatable v2, pager v2, filter row, avatar, view toggle, split button, section strip.
  3. Resolve the 3 conflicts explicitly — either the designer is right (then update the Nimbus docs) or Nimbus is right (then update the mockup). Probably case by case: the sub-nav pill looks nicer, but status text without a pill is objectively cleaner.
  4. Until that happens: we live with expireon-app.css as the application layer for Expireon. Other Cloudficient products could adopt the stylesheet as-is.
